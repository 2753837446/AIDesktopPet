# P12 角色、道具与背景场景资产

## 背景

P11 已能把角色图片编辑成新姿态，但真实桌宠场景不只需要角色本体。用户可能要求“坐在凳子上，旁边有绿植，背景是咖啡馆”，也可能希望分别上传背景和透明道具，在桌宠窗口内组合。只生成一张角色图会丢失场景表达；只做不透明背景又会破坏桌面透明感。

## 目标

- 角色资产明确区分 `character / scene / prop / background`。
- 支持上传背景图与透明前景道具，与角色分层组合。
- 舞台默认保持透明；只有用户主动选择背景或生成完整场景时才出现矩形背景层。
- 支持最多 3 个道具，按左、中、右固定槽位展示，避免首版引入复杂拖拽编辑器。
- AI 生成支持“只改角色姿态”和“生成角色 + 道具 + 背景完整场景”两种模式。
- 完整场景作为单个 `scene` 资产保存；选择后接管分层背景和道具，避免重复叠加。
- 所有资产仍进入现有受控目录、SQLite 元数据、血缘、审计、预览和删除链路。
- 保留原角色与历史场景，任何生成或切换都可回退。

## 成功标准

- 设置页可上传并选择角色、背景和道具；重启后选择恢复。
- 桌宠按背景、道具、角色顺序渲染；未选择背景时默认透明，透明区域始终显示桌面。
- 完整场景资产以整窗方式显示，并禁用其下方独立图层。
- 聊天指令包含“背景、凳子上、旁边、绿植”等场景元素时，可进入完整场景生成确认。
- 用户可明确选择仅角色或完整场景，确认前仍不调用付费服务。
- 历史数据迁移后默认为 `character`，现有角色不受影响。
- 类型检查、单元、E2E、构建和打包通过。

## 不做

- 本轮不做任意拖拽、缩放和锚点编辑器；道具使用三个固定槽位。
- 本轮不做自动抠图、图像分层或把单张合成场景拆回背景和道具。
- 不把完整场景图当成 3D 房间或可自由运镜的 3D 资产。
- 不默认为上传的背景和道具调用外部服务。
