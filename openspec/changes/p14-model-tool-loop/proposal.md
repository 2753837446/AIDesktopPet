# P14 模型工具调用闭环

## 背景

当前 Tool Runtime 已具备 schema、权限、超时、取消、确认和审计，但聊天模型只能返回文本，用户必须进入工具中心手动点“运行”。这让产品仍像聊天窗口，而不是能完成实际任务的桌宠助手。

## 目标

- DeepSeek 流式请求支持 `tools` 和 `tool_calls`。
- 模型可调用低风险和中风险只读工具，首轮包括读取时间、Connector 状态、收件箱列表和指定邮件正文。
- 所有调用继续经过 Tool Runtime 的 schema、scope、超时、取消和审计，不绕过权限层。
- 工具结果回传模型后最多再生成一轮自然语言答复，限制调用数量，防止无限循环。
- 高风险发信与删除不暴露给自动 function calling，继续要求用户在明确确认界面操作。
- UI 显示正在调用工具、完成或失败状态；错误不伪报成功。

## 成功标准

- 用户问“现在几点”时，模型可调用 `clock.read`，最终答复包含真实本地时间。
- 用户明确要求查看最近邮件时，模型可调用 `email.inbox.list`，工具审计产生对应记录。
- 工具参数非法、权限不足、超时或失败时，模型只收到真实错误，不产生虚构结果。
- 一次用户请求最多执行 3 个工具调用，工具结果总长度受限。
- 模型工具调用失败不会破坏普通聊天；取消聊天同时取消可取消工具。
- 单元测试覆盖 SSE tool_calls 聚合、工具成功/失败二次回答、参数校验和高风险隔离。
