# 文档契约基线纠正

## 背景

当前仓库只有规范文档，但任务状态、记忆类型、来源模型、时间格式、数据库字段和 API 契约之间存在冲突。若直接进入实现，会把不一致带入数据库迁移和业务代码。

## 目标

- 统一任务状态、记忆类型、知识来源和处理目的地。
- 统一 UTC RFC 3339 时间格式和用户时区语义。
- 修复记忆来源、候选来源、删除传播和关系重复问题。
- 补齐持久化调度、租约、recurrence、事件恢复和多渠道通知。
- 补齐取消、外部状态对账、Connector 能力和输入上限。
- 建立 README、安全基线和可验证的 SQL/FTS 草案。

## 成功标准

- 所有文档使用同一套任务状态、记忆类型和来源枚举。
- SQL 草案可在 SQLite 内存库中成功执行，FTS5 草案能够创建。
- PRD、架构、记忆、任务、数据/API 和实施计划之间没有互斥定义。
- 明确首版 Windows 支持矩阵和安全边界。

## 不做

- 本变更不实现应用代码。
- 本变更不安装依赖或锁定 Electron、SQLite binding、向量扩展版本。
- 本变更不修改或转码根目录视频文件。
