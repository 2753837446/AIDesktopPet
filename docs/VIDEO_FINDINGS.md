3. 每隔 12–30 秒生成画面缩略图，并对关键时间点抽取高分辨率画面。
4. 用画面核对自动转写中的产品名、URL、模型名、按钮和安全提示。

# 2. 视频一：桌面安装与插件链

## 观察到的事实

- 视频先用“暴喵AI管家”获取免费额度，再安装 DeepSeek Harness 桌面端。
- 桌宠不是 DSH 自带功能，而是通过 `dsh-pet-indesktop` 插件接入；提示中包含仓库地址，并通过 DSH 执行安装任务。
- 安装过程显示检查版本与 SHA-256、下载 Windows 安装包、Inno Setup 静默安装和启动桌宠等步骤。
- 安装器未显示代码签名，首次运行可能触发 Windows SmartScreen；视频建议选择“仍要运行”。
- 桌宠设置中存在模型供应商、API 地址、模型标识、API Key、System Prompt、通知、视觉能力和对话窗口等配置。
- 视频后段安装 `dsh-bili-scroll` 类插件，让桌宠自动刷新、筛选并向用户分享 B 站内容。

## 可借鉴

- 桌宠 UI、Agent 运行时、模型供应商和插件通过桥接层解耦。
- 角色展示与设置窗口分离；右键进入设置符合桌面应用习惯。
- API Key 输入使用密码框，并提示保存到系统凭据库。
- 插件可以扩展浏览、通知或工具能力，但应通过明确的 Capability 清单和权限门控接入。
- 软件安装可验证版本、哈希和安装结果，便于诊断。

## 不能照搬

- “完全权限”应由最小权限和逐步授权替代；普通安装不应要求 Agent 长期拥有系统级操作权限。
- 未签名安装包和 SmartScreen 绕过不能成为正式产品路径；发布包应签名并验证更新来源。
- 自动浏览依赖登录态、平台风控和第三方插件，可能触发验证码或账号限制，不能作为首版核心能力。
- 视频包含产品和模型服务推广，短视频中的“零成本”“全本地”等说法不能直接作为架构或费用结论。

# 3. 视频二：QQ、长期记忆与主动反馈

## 观察到的事实

- 技术链路为 AstrBot、NapCat、QQ 小号、OneBot v11、DeepSeek、豆包语音、BGE-M3 和角色配置包。
- AstrBot 与 NapCat 通过反向 WebSocket 连接，配置包含主机、端口、token、心跳和重连间隔。
- 教程先设置访问白名单和管理员，再关闭默认电脑操作能力，之后才导入人格、插件、表情包和参数。
- 长期记忆依赖独立插件和 BGE-M3 embedding；可选择本机 Ollama 或硅基流动 API。每次回复前检索相关历史，避免把全部聊天记录塞入上下文。
- 视频把清除聊天上下文描述成“忘记用户”，证明长期记忆必须与短期会话上下文分开。
- 主动性包括定时提醒、深夜免打扰和主动消息；QQ 空间自动发布默认关闭。
- DSH 自动化部分步骤时，提示词要求 Agent 读取明文保存的后台密码、QQ 号、API Key 和语音 Token，并保证“不显示”。
- 视频明确提醒 API Key 等同于账户余额，不能泄露。
- 抖音、B 站等自动互动受到验证码、实名认证或风控限制；视频作者未全部实测成功。

## 可借鉴

- 白名单、所有者身份和禁用高风险能力的顺序值得直接采纳。
- 长期记忆采用独立存储与 embedding 检索，与具体聊天通道解耦。
- 本地与云端 embedding 可以通过同一 Provider 接口切换，并显式标记处理目的地。
- 任务提醒需要时区、时间确认、免打扰和主动消息设置，但必须落到持久化任务引擎。
- Connector、语音、记忆和社交动作应作为独立插件或能力，不应耦合进 Assistant Core。

## 不能照搬

- 明文凭据文件不可进入正式方案。密钥必须进入 Windows 凭据库，Agent 只获得短期、最小权限的句柄。
- “告诉模型不要显示密钥”不是安全控制；模型仍可能读取、记录或在错误中泄漏敏感值。
- QQ 小号、NapCat 和常驻终端属于非官方、高维护成本的消息通道，应作为可选 Connector，不阻塞桌宠启动。
- 豆包语音更像真人但付费且有约 20 秒首响，免费 TTS 又较机械；语音不应成为 MVP 阻塞项。
- 通过 Prompt 或插件“自己定闹钟”无法代替持久化 Scheduler、幂等和重启恢复。
- 自动刷 B 站、抖音自动互动、自动发 QQ 空间等能力默认关闭，首版不实现。

# 4. 对当前项目的直接决策

| 能力 | 结论 | 理由 |
| --- | --- | --- |
| Windows 2D 桌宠与设置入口 | 首版采纳 | 两个视频都验证了桌面存在感和低摩擦设置体验 |
| 模型 Provider 适配 | 首版采纳 | 视频至少使用 DeepSeek，并支持不同聚合服务 |
| BGE-M3 + 混合检索 | 首版技术验证 | 视频证明可行，但还不能证明记忆质量、可追溯性和删除一致性 |
| 独立长期记忆 | 首版必须 | 清空聊天上下文就失忆，说明上下文不等于长期记忆 |
| 持久化任务/提醒 | 首版必须 | 视频中的主动提醒不能证明崩溃恢复和幂等 |
| 本地/云端处理目的地 | 首版必须 | 本地 embedding 与云端 API 均出现，隐私边界必须显式 |
| 白名单和最小权限 | 首版必须 | 视频已展示未授权接入和费用风险 |
| QQ / NapCat | 后续可选 Connector | 非官方通道、增加运行依赖并对平台风控敏感 |
| 豆包语音 | 后续可选 Provider | 付费、延迟较高，不能阻塞 MVP |
| 自动刷视频/发空间 | 不进入 MVP | 账号风控、确认成本和内容安全风险高 |
| Agent 完全权限安装 | 拒绝 | 与最小权限、可审计和高风险确认原则冲突 |
| 明文凭据文件 | 拒绝 | 违反密钥管理基线 |

# 5. 视频没有证明的能力

以下仍需由本产品自行设计和验证，视频不能作为完成证据：

- 记忆来源展示、冲突版本、用户纠正、删除传播和索引重建。
- 任务状态机、租约、幂等、重启恢复、时区与夏令时规则。
- `local_only` 数据不进入云端模型的强制校验。
- 插件权限范围、工具调用审计和高风险动作确认。
- 签名安装包、自动更新、安全回滚和干净 Windows 环境安装。
- 长期运行的内存、CPU、磁盘、通知频率和模型成本基线。

# 6. 建议的下一步验证

1. 先做桌宠壳与设置页，验证透明窗口、托盘、开机自启和未配置模型时的可用性。
2. 用 100–500 条模拟历史验证 BGE-M3 + FTS5 的中英文检索、来源过滤和预算裁剪。
3. 用 SQLite 实现 tasks、task_runs、occurrence、lease 和 notifications，验证重启与重复事件。
4. 再做 DeepSeek Provider 和一个无副作用工具，最后评估邮件或 QQ Connector。
