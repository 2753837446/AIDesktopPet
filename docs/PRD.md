# PRD.md｜Windows AI 桌宠产品需求文档

*产品定位、MVP 范围、用户流程、功能需求、非功能要求与验收标准*

版本：V0.4 · 日期：2026-10-27

# 1. 产品定位

产品暂定为 Windows AI 桌宠 / AI 助手。桌面角色是用户日常接触的入口，底层提供对话、长期记忆、任务执行、每日总结和主动反馈。产品不应仅是聊天窗口，也不应依赖某个机器人消息渠道才能工作。

## 产品愿景

让桌宠随着使用时间增加而越来越了解用户，并能在得到授权的范围内主动提醒、整理信息、推进任务；同时保持安装简单、运行稳定、行为可控。

## 目标用户与使用场景

- 希望桌面有常驻 AI 角色，能自然对话并保留长期背景的 Windows 用户。
- 需要每日整理任务、邮件、日程或工作记录的个人用户。
- 希望通过 Agent 执行有限、可审核任务的开发者和效率用户。

# 2. 产品目标与成功标准

| 目标 | 可观察指标 |
| --- | --- |
| 安装简单 | 普通用户可通过单安装包完成安装；首次启动可跳过 AI 配置 |
| 长期记忆可靠 | 支持回忆用户明确偏好、项目决定和历史事件，并能查看来源 |
| 响应速度稳定 | 检索与上下文组装延迟可测量；长历史不会导致每次请求上下文持续膨胀 |
| 主动反馈有价值 | 每日总结、到期提醒、失败通知能按用户设置触发，重复率可控 |
| Agent 行为可控 | 工具调用有权限检查、执行日志和必要的用户确认 |
| 基础功能可靠 | 模型或 Agent 失败时桌宠 UI 仍可用；应用重启后任务状态可恢复 |

# 3. MVP 范围

## 必须包含

- Windows 10 22H2 x64 与 Windows 11 x64 桌面应用；首版以无需管理员权限运行和安装为目标，ARM64 仅在有验证结果后声明支持。支持 2D 桌宠、透明常驻窗口、拖动、基础动画、系统托盘，以及用户上传 PNG / GIF / WebP 图片切换角色形象。
- 支持从当前自定义形象生成新姿态：用户可在聊天或设置中用自然语言描述“坐在凳子上”等动作；外部生成前必须确认参考图、描述、模型、云端上传与可能费用，结果先预览，用户确认后才切换。
- 首次启动向导、模型连接配置、可跳过 AI 配置、可选开机自启和最小化启动。
- AI 对话、流式回复、角色人格配置。
- 基础长期记忆：用户偏好、重要决定、承诺、项目摘要和事件检索；事实、用户明确表达和模型推断必须分别标记，用户可以查看、纠正和删除。
- 上下文预算与压缩机制，原始历史和结构化记忆分开保存。
- 任务管理：手动任务、重复任务、截止日期、状态、失败与重试。
- 主动反馈：每日总结、到期提醒、任务失败通知、免打扰与频率设置。
- 基础工具调用：工具注册、参数校验、权限检查、执行日志。
- 先接本地任务 / 日程数据，再接一个用户选择的主邮箱。

## 首版明确不做

- 不要求 QQ、NapCat、AstrBot 或其他 Agent runtime 成为桌宠启动依赖。
- 不首发完整 3D 角色、游戏系统或创作者交易市场。
- 不默认开启高权限自动化，不允许无确认地发送邮件、删除文件或执行不可逆操作。
- 不把所有历史对话直接塞入每次模型上下文。
- 不在未授权的情况下读取邮箱、日历或本地文件。

# 4. 核心用户流程

## 首次启动

1. 安装并启动桌宠。
2. 选择角色 / 基础形象和是否开机自启。
3. 可选配置模型服务；也可以先跳过，使用基础桌宠。
4. 展示数据存储、隐私与权限说明。
5. 进入桌面，桌宠显示可用能力与尚未配置的能力。

## 日常对话与记忆

1. 用户发起对话。
2. 系统判断当前意图和项目上下文。
3. 检索少量相关记忆并按预算组装上下文。
4. 模型生成回复或提出工具调用。
5. 工具调用通过权限和参数校验。
6. 后台提取候选记忆；重要决定与承诺按规则写入结构化存储。
7. 用户可在记忆中心查看、纠正或删除记忆。

## 主动提醒

1. 用户创建任务或明确启用自动化规则。
2. 调度器持久化保存规则和执行状态。
3. 到期或事件触发时，规则引擎检查频率、免打扰和权限。
4. 需要语义分析时调用模型；确定性提醒直接生成。
5. 桌宠展示通知，用户可完成、延期、忽略或关闭该类提醒。

# 5. 功能需求

## 5.1 桌宠与桌面

- 支持透明窗口、拖动、基础待机 / 说话 / 提醒动画。
- 支持上传透明背景 PNG、GIF、WebP 自定义形象；资产本地持久化，重启后恢复选择并允许删除。
- 每张形象可标记正面、侧面、背面或待机 / 说话 / 思考等视图，为多视图动作系统保留数据。
- AI 姿态必须创建新的派生资产并保留来源、提示词、模型和生成时间；不得覆盖原图或自动替换当前形象。
- 桌宠舞台默认完全透明；用户可额外上传背景图与最多 3 个透明前景道具，分层组合时不默认添加矩形底图。
- 支持 AI 生成“角色 + 道具 + 背景”的完整场景，但必须作为独立 `scene` 资产预览；完整场景可接管独立背景与道具层，不得重复叠加。
- 支持系统托盘菜单：打开面板、暂停主动提醒、设置、退出。
- 记住用户选择的角色、窗口位置、大小和显示偏好。
- Agent 或模型异常时 UI 不崩溃，并显示可理解的状态。

## 5.2 对话与角色

- 支持流式输出、停止生成、重试和错误提示。
- 角色配置包含人格、说话风格、行为边界、主动性偏好和版本。
- 角色资产与用户长期记忆分离；切换角色不清空记忆。
- 角色运行时应通过统一接口支持静态图片、GIF、Sprite Sheet、分层骨骼 2D 和未来 GLB 3D 适配器。
- 单张 AI 姿态属于新形态候选，不等同于骨骼动画或可自由驱动的 3D 模型；跨角度与连续动作需要后续多视图、关键帧或 GLB 资产。
- 模型适配层允许切换不同模型服务。

## 5.3 长期记忆

- 原始消息、候选记忆、确认后的记忆、摘要和任务状态分开存储。
- 支持关键词 + 向量混合检索、项目过滤、时间过滤和上下文预算裁剪。
- 记忆条目展示内容、类型、来源、创建时间、可信度 / 状态及是否为推断。
- 支持编辑、删除、标记错误和查看被替代版本。
- 记忆冲突时保留历史，必要时向用户确认。

## 5.4 任务与主动反馈

- 支持一次性、重复、事件触发和每日总结任务。
- 状态包括待执行、已安排、执行中、等待确认、等待重试、已完成、失败、已取消、已过期和等待外部状态对账。所有模块使用同一状态枚举和迁移规则。
- 应用重启后恢复未完成任务；重复事件不会导致重复执行。
- 通知支持免打扰、类别开关、每日上限和延期。
- AI 建议的任务必须经用户确认后进入正式任务列表。

## 5.5 邮件与外部连接器

- 采用官方授权 API / 推送 / 受控轮询；最小权限原则。
- 支持规则过滤、去重、重要性筛选，再按需调用 AI 摘要。
- 连接器显示授权状态、最近同步时间、错误和撤销入口。
- 邮件正文与外部文件视为不可信数据，不得覆盖系统规则。
- 发送、删除、外部提交等高风险动作需确认。

# 6. 非功能需求

| 领域 | 要求 |
| --- | --- |
| 性能 | 分别记录检索延迟、上下文组装延迟、模型首字延迟和完整回答耗时 |
| 稳定性 | 崩溃后恢复任务；索引失败可重建；模型故障不影响基础桌宠 |
| 隐私 | 明确本地与云端处理边界；授权可撤销；密钥安全存储 |
| 安全 | 工具输入校验、权限分级、外部内容提示注入防护、敏感操作确认 |
| 可维护性 | 模块化、版本化数据库迁移、统一日志与诊断 |
| 可移植性 | 模型、embedding、Agent runtime 和连接器可替换 |

# 7. 关键页面

| 页面 / 界面 | 主要内容 |
| --- | --- |
| 桌面角色 | 角色本体、状态动画、轻量气泡、通知入口 |
| 聊天面板 | 消息流、输入框、停止生成、重试、当前项目提示 |
| 每日总结 | 今日重点、日程、待办、重要邮件摘要、建议与数据源状态 |
| 任务面板 | 列表、优先级、截止日期、状态、延期 / 完成 / 重试 |
| 记忆中心 | 按用户档案 / 项目 / 事件分类，搜索、编辑、删除、来源查看 |
| 主动性设置 | 免打扰、通知类别、每日上限、主动性等级 |
| 连接器设置 | 模型提供商、邮箱 / 日历授权、连接状态、撤销权限 |
| 角色设置 | 人格、说话风格、边界、主动性配置、导入 / 导出配置 |

# 8. MVP 验收标准

- 在安装有 Windows 10 22H2 x64 或 Windows 11 x64 的干净环境中安装后可启动桌宠，无需用户单独安装开发运行时；首版不承诺 ARM64 支持。
- 模型未配置时仍可打开桌宠，明确显示 AI 功能尚未启用。
- 连续积累大量历史后，普通请求只加载有限上下文，检索能找回相关记录。
- 记忆可查看、纠正和删除；删除后索引与缓存不再返回该条记录。
- 提醒在应用重启后仍能执行，重复事件不重复通知。
- 每日总结只使用真实可用的数据源，失败时明确展示缺失来源。
- 高风险工具动作未获用户确认前不会执行。
- 模型或 Agent runtime 故障时，桌宠 UI 仍可操作。
- 自定义图片上传后可以切换并在重启后恢复；非法格式、超限图片和损坏资产回退内置角色。
- 输入“让她坐在凳子上”等动作指令时先显示确认，不直接调用付费生图或覆盖形象；生成成功后必须经过预览和“设为桌宠”二次选择。
- 请求包含“旁边有绿植、背景是咖啡馆”等场景元素时，确认卡应明确显示将生成完整场景，而不是只生成角色。
- 生图超时、取消、限流、认证失败和返回非法图片均有稳定错误码，当前形象保持不变。
- 未选择背景时桌宠窗口保持透明；背景、道具和完整场景均可独立删除并回退到透明舞台。

# 9. 风险与依赖

- Agent 框架许可证和商业分发方式需提前评估。
- BGE-M3 服务可用性、API 模型标识、限额和费用需在开发前核验。
- 图像编辑服务的模型可用性、内容审核、结果格式、费用和临时链接有效期需持续核验；返回图片必须立即下载并重新校验。
- Windows 打包、透明窗口、开机自启和系统通知需在真实目标系统验证。
- 多视图图片不是可直接动画的 3D 资产；真正 3D 需要 GLB、骨架、蒙皮和动作片段，并完成性能与许可证验证。
- 邮箱授权能力依赖具体服务商，不能假定所有邮箱均有相同 API。
- 长期记忆质量必须依赖测试集持续评估，不能只通过主观聊天体验判断。
