# Personal Companion PRD

版本：V0.1 · 2026-10-28

## 产品定位

个人数字伙伴平台。每位用户拥有一个私人数字空间，可创建一个或多个有独立人格、记忆、外观和任务能力的数字伙伴。伙伴不只提供问答，也承担任务执行、生活整理和情绪陪伴。

## 核心原则

- 伙伴身份与形象分离。
- 外观可换，关系和记忆不丢。
- 多设备共享记忆，但设备私有信息不上云。
- 多个伙伴的记忆和权限互相隔离。
- 高风险外部动作必须确认并可审计。
- 数字伙伴不是单一聊天窗口，也不是单一桌宠皮肤。

## MVP 范围

- 个人 Workspace 初始化与登录。
- 多设备访问。
- 多个数字伙伴创建和切换。
- 独立人格、外观、会话和记忆作用域。
- 基础聊天、流式输出和任务管理。
- 响应式 Web 客户端。
- 可 Docker 部署的个人后端。

## 暂不包含

- 公共社交、好友和多人协作。
- 云端模型强制绑定。
- 完整 3D、骨骼和动作商店。
- 支付、订阅和创作者市场。

## 后续必须能力：智能家居与智能场景

智能家居明确属于产品长期范围，但不阻塞第一版。第一版优先完成个人 Workspace、多个数字伙伴、跨设备记忆、任务和权限。

后续能力包括：

- 通过 Home Assistant、Matter、MQTT、厂商云 API 等 Connector 接入家庭设备。
- 统一描述房屋、房间、设备、能力、状态和在线情况。
- 支持灯、空调、窗帘、插座、传感器等低风险设备。
- 支持门锁、车库、报警器、燃气和加热设备等高风险管理。
- 支持由时间、设备状态、日历、位置和用户意图触发的智能场景。
- 数字伙伴可以提出场景建议、解释执行计划，并在用户确认后执行。
- 多设备共享家居状态和场景，但设备凭证、摄像头和位置数据按最小权限处理。

## 智能家居 MVP 边界

首个智能家居版本优先接入一个成熟家庭自动化中心，推荐 Home Assistant，而不是一开始自行实现所有厂商协议。智能场景先采用确定性规则和手动确认；LLM 只负责理解意图、起草和解释，不直接替代安全联锁。
