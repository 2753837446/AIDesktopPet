# CHARACTER_RUNTIME.md｜桌宠角色展现与 3D 演进

版本：V0.3 · 日期：2026-10-27

# 1. 目标

桌宠展现优先于普通聊天窗口。角色需要支持用户自定义形象、多视图、动作状态和未来 3D，而不把 UI 与某个图片、Live2D、3D 引擎或 Agent runtime 绑定。

# 2. 当前 P10 / P11 / P12 实现

- 支持上传 PNG、GIF、WebP，单张最大 10 MiB、最大 4096×4096。
- 拒绝 SVG、脚本格式和伪造 MIME。
- 图片按 UUID 存入 `userData/character-assets/`，元数据写入 SQLite。
- 上传后可立即切换；选择记录在 DesktopSettings。
- 删除当前形象后回退到内置角色。
- GIF 可提供基础循环动画；静态图片只提供形态切换，不宣称可自动运动。
- P11 支持从当前选中的 PNG / WebP / JPEG 自定义形象生成单张 AI 姿态候选。
- 用户可在聊天输入“让她坐在凳子上”等动作，或在设置页写姿态描述；首次提交只显示确认卡。
- 确认后才调用 `Qwen/Qwen-Image-Edit-2509`，只发送单张参考图、固定保真模板和姿态描述。
- 生成结果立即下载并保存为新资产，记录源资产、提示词、模型和生成时间；不覆盖原图。
- 结果先显示为候选，用户点击“设为桌宠”后才更新选择；原图与历史候选可随时切回。
- 单张姿态图是一次形态切换，不是骨骼动画；连续挥手、走路等仍需后续帧序列或骨架。
- P12 把资产分为角色、完整场景、透明道具和背景；默认舞台完全透明。
- 用户可上传背景和最多 3 个透明道具，与角色分层组合；未选择背景时不绘制矩形底图。
- AI 生成可选择“仅角色姿态”或“角色 + 道具 + 背景完整场景”。
- 完整场景保存为独立 `scene` 资产，选择后接管背景和道具层，避免重复叠加。

# 2.1 AI 角色与场景流水线

```text
聊天动作指令 / 设置页描述
  -> 本地确定性识别
  -> 用户确认参考图、模型、云端上传与可能费用
  -> CharacterImageEditProvider
  -> 返回结构、URL、图片魔数、尺寸、大小校验
  -> 新 CharacterAsset（origin=ai_generated, category=character/scene）
  -> 候选预览
  -> 用户确认“设为桌宠”
```

安全与失败边界：

- 图像 Provider 不接收会话、记忆、API Key、其他角色资产或工具权限。
- 结果 URL 仅接受公网 HTTPS，并立即下载；一小时临时链接不作为持久存储。
- 单次总超时 120 秒，支持取消；同一时间只允许一个付费生成任务。
- 超时、取消、限流、认证失败、非法响应和不安全 URL 都有稳定错误码，当前形象保持不变。
- 图片内文字属于不可信内容，不能触发工具或修改系统规则。

# 2.2 分层舞台

```text
可选背景层
  -> 最多 3 个透明道具（左 / 中 / 右固定槽位）
  -> 角色层
  -> 状态气泡与操作 UI
```

- 默认 `customBackgroundId=null`，窗口透明区域直接显示桌面。
- 背景使用 `object-fit: cover`；道具和角色保持透明并独立缩放。
- 选择 `scene` 时不渲染独立背景和道具，完整场景使用整窗 `object-fit: cover`。
- 分层组合是视觉运行时能力；它不会把一张完整场景自动拆成背景、道具和角色。

# 3. 统一角色状态

角色适配层只消费状态，不直接理解聊天或任务：

| 状态 | 用途 |
| --- | --- |
| idle | 空闲待机 |
| talking | 模型流式输出 |
| thinking | 模型或工具处理中 |
| dragging | 用户拖动窗口 |
| happy | 用户确认、任务完成 |
| sleepy | 长时间无交互或免打扰 |

后续可增加 listening、working、error、celebrating。

# 4. Character Runtime 接口

```text
CharacterRuntime
  initialize(profile)
  setState(state)
  playAction(action, options)
  setScale(scale)
  dispose()
```

适配器：

- ImageCharacterAdapter：静态图片或 GIF。
- PoseDirectorAdapter：从单帧形象生成新的动作候选，经用户确认后切换。
- LayeredStageAdapter：背景、道具和角色分层组合；未选择背景时保持透明舞台。
- SpriteSheetAdapter：按状态切换帧序列。
- Rigged2DAdapter：多视图拆分 + 骨骼 / 网格。
- Gltf3DAdapter：GLB 模型、骨架与动画片段。

UI 只依赖接口，不在 UI 中写死动画格式。

# 5. 多视图角色包

参考漫剧制作方式，建议角色资产包含：

- Turnaround：front、left、right、back。
- 表情表：平静、开心、疑惑、难过、害羞、生气。
- 动作关键姿态：待机、说话、思考、伸手、走路、坐下、睡眠。
- 场景层：可选背景、透明道具、固定槽位和完整 scene 合成图。
- 角色图层：身体、头发、眼睛、嘴、眉毛、配饰。
- 元数据：角色名、作者、许可、版本、画布尺寸、锚点、比例。

存储目录示例：

```text
character-pack/
  manifest.json
  views/front.webp
  views/left.webp
  views/right.webp
  expressions/happy.webp
  actions/talking.json
```

所有配置必须 schema 校验，不执行包内脚本。

# 6. 2D 动态实现路径

1. 静态图片 / GIF：当前阶段。
2. 多帧 Sprite Sheet：低成本实现待机、说话和表情切换。
3. 分层网格 / 骨骼：参考 Live2D 类能力，但需评估许可证、运行时和制作工具。
4. 多视图混合：根据转头角度在 front/left/right/back 图之间过渡，适合低帧率转向。

# 7. 3D 实现边界

多视图图片可以作为 3D 建模、贴图和 Rig 的参考，但不能直接等同于可动画 3D 模型。真正 3D 需要：

- glTF 2.0 / GLB 模型。
- 骨架与蒙皮权重。
- idle、talking、thinking、walking 等动画 Clip。
- 表情 Blend Shape 或材质参数。
- 合规许可证和明确来源记录。

3D 适配器应运行在独立渲染上下文，模型失败不能影响 Assistant Core、记忆和任务。

建议演进：

1. 先用多视图和动作关键帧验证角色表现与用户偏好。
2. 将 AI 姿态资产按角色、动作、视角和版本组织，形成可复用动作库。
3. 再评估自动建模 / 绑骨工具的质量和许可证。
4. 3D 必须经过性能、显存、启动时间和崩溃恢复测试。

# 8. 安全与隐私

- 不加载 SVG 或可执行角色包。
- 图片和模型只从受控用户数据目录读取。
- 不在角色包中保存 API Key、记忆或用户隐私。
- AI 生图前展示参考角色、动作、模型、云端处理和可能费用；用户确认后才发出请求。
- 生成结果 URL、图片正文和模型响应均视为不可信输入；不执行图片内指令。
- 外部生图失败或取消不改变当前角色；结果不确定时提示用户，不自动重复付费请求。
- 默认舞台不创建背景；背景、道具和完整场景仅在用户主动选择或确认后出现。
- 背景与道具只作为受控图片渲染，不执行配置、脚本或图片内指令。
- 导入包校验版本、大小、字段、哈希和许可证信息。
- 记录用户上传资产的删除入口和实际文件清理状态。

# 9. 验收标准

- 自定义图片上传后可显示，重启后仍可恢复选择。
- 非法图片被拒且不影响现有角色。
- 聊天动作指令先进入确认态，未确认时不发起生图请求。
- AI 生成成功后先作为候选展示，原资产、源关系和切换入口均保留。
- 生成超时、取消、限流和内网结果 URL 均被安全处理并可理解提示。
- 未选择背景时桌宠窗口保持透明；选择背景后按背景、道具、角色顺序显示。
- 最多 3 个道具可独立移除；完整场景不重复叠加独立背景和道具。
- 角色渲染异常时可回退内置角色并显示可理解错误。
- 状态切换不阻塞聊天流和任务调度。
- 3D 适配器接入时不需要修改 Assistant Core 或 Memory Service。
