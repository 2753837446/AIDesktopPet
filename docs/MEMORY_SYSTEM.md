# MEMORY_SYSTEM.md｜长期记忆系统设计

*面向 Windows AI 桌宠的记忆数据模型、写入、检索、压缩与评测规范*

版本：V0.2 · 日期：2026-10-27

# 1. 目标与非目标

目标：让桌宠在长时间使用后仍能找回重要事实和决策，控制每次推理加载的上下文规模，并允许用户检查、纠正和删除记忆。记忆服务应独立于具体模型和 Agent runtime。

- 保存原始对话和重要事件，避免摘要成为唯一证据。
- 将事实、偏好、推断、项目决定、经历事件、任务状态分开管理。
- 按需检索而不是全量拼接；同时支持语义相似和准确关键词检索。
- 记录来源、可信度、有效期、版本和冲突关系。
- 支持离线 / 本地优先运行；云端模型调用与数据出站必须清晰可控。

## 非目标

- 不试图把所有历史永久放进模型上下文。
- 不把向量数据库当作完整记忆系统。
- 不允许模型未经规则验证就直接覆盖重要事实或执行任务。
- 不把短期对话摘要当作用户长期档案。

# 2. 记忆分类与生命周期

| 类型 | 示例 | 默认生命周期 | 写入要求 |
| --- | --- | --- | --- |
| 工作记忆 | 当前会话主题、最近消息、当前工具调用 | 会话期间，可滚动压缩 | 自动维护，保留最近对话 |
| 用户档案 | 长期偏好、语言习惯、明确要求 | 长期，允许用户编辑 / 删除 | 明确事实与推断分开；重要项可确认 |
| 项目记忆 | 项目目标、范围、已否决方案、决策理由 | 项目生命周期 | 绑定 project_id，记录版本和来源 |
| 事件记忆 | 某天发生的讨论、执行结果、失败经验 | 长期可检索，可归档 | 保留时间、事件类型和原始来源 |
| 任务状态 | 截止日期、待办、重复任务、执行状态 | 直到完成 / 取消 / 过期 | 结构化存储，不仅写入文本 |
| 摘要记忆 | 会话摘要、项目摘要、阶段总结 | 可重建、可版本化 | 必须能追溯所依据的原始记录 |

## 记忆生命周期

1. 采集原始记录。
2. 识别候选记忆并分类。
3. 去重、合并、检查冲突与时效。
4. 按规则决定自动保存、等待用户确认或不保存。
5. 写入结构化库与搜索索引。
6. 按需检索并组装上下文。
7. 依据用户纠正、项目变化和新证据更新版本。
8. 归档低频记忆，但保留可搜索性和来源。

# 3. 数据模型建议

## 3.1 memories 表

| 字段 | 类型 / 说明 | 要求 |
| --- | --- | --- |
| id | UUID / 本地唯一 ID | 主键 |
| type | profile / preference / fact / project_decision / event / summary / commitment | 必填 |
| origin | user_explicit / model_inferred / imported / verified | 必填；知识来源性质，不是渠道类型 |
| content | 规范化后的记忆内容 | 必填 |
| project_id | 所属项目，可为空 | 项目记忆必填 |
| sources | 通过 memory_sources 关联会话、消息、任务、文件、连接器或用户编辑 | 至少一个可追溯来源 |
| confidence | 0–1 可信度 | 必填；模型推断不得默认 1.0 |
| importance | 0–1 重要性 | 用于排序，不等同于真实性 |
| status | active / superseded / archived / deleted | 必填 |
| created_at | 创建时间 | 必填 |
| updated_at | 更新时间 | 必填 |
| last_confirmed_at | 最近确认时间 | 可空 |
| expires_at | 过期时间 | 可空 |
| privacy_level | normal / sensitive / local_only | 必填 |
| embedding_status | pending / indexed / failed / excluded | 索引维护 |

`memories` 不保存第二套来源字段；所有来源统一写入 `memory_sources`。替代、支持和冲突关系统一写入 `memory_links`，避免 `supersedes_id` 与链接表同时维护而产生分歧。

## 3.2 conversation_messages 表

- 保存原始消息或受控保留的消息副本，字段包括 id、conversation_id、role、content、created_at、token_estimate、project_id、source、retention_policy 和 deleted_at。
- 原始记录与摘要分开保存。用户删除原始消息时立即移除对应来源摘录并加入清理队列；若某条派生记忆没有其他独立来源，则标记为不可检索并等待用户复核或清理。

## 3.3 项目状态表

- `project_state_current` 保存项目当前目标、范围、关键约束、已决定事项、未决问题、下一步和当前版本号。
- `project_state_versions` 保存每次变化的版本快照，支持追溯；不能用一个 `PRIMARY KEY(project_id)` 的表伪装成历史版本表。
- 项目摘要是可重建的缓存视图，不应取代结构化决定记录。

## 3.4 memory_links 表

- 记录 related_to、supports、contradicts、supersedes、derived_from 等关系，并作为关系事实的唯一来源。
- 关系用于处理冲突、追溯证据和项目内导航；首版可先实现 supersedes 与 derived_from。

# 4. 记忆写入策略

## 4.1 候选记忆识别

- 重要决定：用户明确说“决定 / 采用 / 不再使用 / 范围冻结”等。
- 长期偏好：反复出现、明确要求未来持续遵守的偏好。
- 承诺和待办：提醒、截止日期、计划继续做的事情，必须同时进入任务系统。
- 事件经验：任务失败原因、有效解决方案、用户明确认可的结果。
- 临时闲聊和低价值重复内容默认不进入长期语义档案，但原始记录可按保留策略留存。

## 4.2 写入决策规则

| 候选类型 | 默认动作 | 备注 |
| --- | --- | --- |
| 明确的长期偏好 | 自动写入候选记忆 | 高影响偏好可提示用户确认 |
| 项目范围 / 架构决定 | 写入项目记忆并保留来源 | 变更时建立新版本，不直接抹掉历史 |
| 模型推断的偏好 | `origin=model_inferred`，较低置信度 | 不能伪装成用户明确事实 |
| 带时间的提醒 / 承诺 | 写入任务系统 | 同时可生成事件记忆，但任务状态以结构化表为准 |
| 敏感信息 | 默认最小化保存 | 按用户授权和本地 / 云端策略处理 |
| 重复信息 | 合并或增加证据次数 | 避免生成多个互相重复的记忆 |

## 4.3 冲突处理

1. 先判断是否真正冲突，还是适用范围不同。
2. 检查时间、项目、来源和用户是否明确撤销旧决定。
3. 对低风险偏好可按新证据更新并保留版本历史。
4. 对高影响决策、敏感事实或无法判断的冲突，向用户提问。
5. 将旧记录标记 superseded，不做无痕覆盖。

# 5. 检索与上下文组装

## 5.1 检索管线

1. 解析当前问题，识别项目、实体、时间范围和任务意图。
2. 先读取固定小型上下文：角色规则、用户基础档案摘要、当前会话状态。
3. 并行执行全文检索、向量检索和元数据过滤。
4. 合并候选、去重并根据相关性、重要性、时效、可信度和项目匹配重排。
5. 裁剪到当前请求预算。
6. 将关键记忆与来源摘要一起交给模型。
7. 记录本次命中、未命中和用户纠正结果，用于评测。

## 5.2 排序信号

- 语义相关性与关键词命中。
- 项目 ID 和实体匹配。
- 时间接近度与有效期。
- 重要性、可信度、用户确认状态。
- 记忆类型与当前意图匹配。
- 是否为已被替代、过期或删除的记录。

## 5.3 上下文预算建议

预算应由模型窗口、任务复杂度和响应时延目标动态决定。可以用系统规则 / 角色、最近对话、用户档案、项目摘要、检索记忆、工具说明和输出余量构成预算表。此前示例预算：系统规则与角色 1,500 tokens；当前对话 4,000；用户档案 800；项目摘要 1,200；相关记忆 2,000；其余留给任务、工具与输出。这只是初始实验值，需要基准测试后调整。

# 6. BGE-M3 与检索组件

- BGE-M3 用于文本向量表示和语义检索，不负责生成对话、持久化记忆或主动提醒。
- 首版建议 BGE-M3 向量检索 + SQLite FTS5 全文检索 + 元数据过滤。
- 不要一开始实现所有高级检索方式；先用测试集比较召回率、误召回率和延迟。
- 如果后续加入重排序模型，应衡量其额外延迟和成本是否带来足够提升。
- 模型 API 与本地 embedding 都应抽象成接口，允许后续切换服务提供方。

# 7. 缓存、归档与数据安全

- 缓存用户档案、项目摘要和近期检索结果，但每次写入 / 修改 / 删除都要触发相应缓存失效。
- 低频记忆可归档但保持可检索；不能仅因为很久没访问就删除重要决定。
- 原始数据、摘要、向量索引和派生记忆之间应能追溯关联。
- 删除记忆需要同步处理全文索引、向量索引、缓存和派生摘要，必要时重建项目摘要。
- 本地数据库应支持备份与恢复；对损坏、迁移失败和磁盘空间不足提供可诊断错误。

# 8. 记忆服务接口建议

```text
POST /memory/candidates
输入：source_kind、source_id、content、project_id、event_type
输出：候选记忆列表、分类、置信度、建议动作

POST /memory/commit
输入：候选记忆 ID、确认状态、保留策略
输出：memory_id、索引状态

POST /memory/search
输入：query、project_id、types、time_range、top_k、token_budget
输出：排序后的记忆片段、来源、相关性分数

PATCH /memory/{id}
输入：content / status / expires_at / privacy_level
输出：更新版本与索引状态

DELETE /memory/{id}
动作：删除或软删除，并同步索引、缓存及派生记录

POST /memory/rebuild-index
动作：从有效记忆重建全文 / 向量索引
```

# 9. 评测集与验收标准

- 准备至少覆盖事实回忆、项目决策、相似表达、准确关键词、跨项目隔离、矛盾更新、时间过期和用户删除的测试集。
- 每条测试问题应标注期望记忆 ID 或期望答案证据，而不只是主观判断回答是否流畅。
- 记录 Recall@K、Precision@K、错误项目命中率、事实错误率、检索 P50 / P95 延迟、上下文 Token 数和端到端延迟。
- 必须测试记忆删除后不能从缓存、索引或摘要中重新泄漏。
- 对模型无法确定的情况，允许明确回答“没有找到可靠记录”，优于编造历史。

# 10. 首版实施顺序

1. 先建立原始消息、memories、记忆来源、`project_state_current`、`project_state_versions` 和任务关联表。
2. 实现结构化记忆写入、用户可查看和编辑。
3. 接入 SQLite FTS5，先打通精确检索。
4. 接入 BGE-M3 embedding 与向量检索，并分别覆盖结构化记忆、原始消息和授权文件片段。
5. 实现混合召回、去重、元数据过滤和预算裁剪。
6. 实现冲突版本、缓存失效和索引重建。
7. 建立回归测试集与延迟指标，再决定是否加重排序和更复杂的记忆整理模型。
